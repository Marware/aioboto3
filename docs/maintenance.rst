Maintaining this fork
====================

The fork at https://github.com/Marware/aioboto3 follows aiobotocore releases.
The supported Python versions are 3.10 through 3.14. boto3 is a direct dependency
because aiobotocore 3 removed its boto3 extra. Its version is selected by the
resolver within aiobotocore's botocore requirements; tracking the newest boto3
release is not a separate goal.

Dependency updates
------------------

Dependabot checks aiobotocore weekly and opens pull requests updating the exact
pin in ``pyproject.toml`` and the resolved packages in ``uv.lock``. The fork must
have GitHub Actions and Dependabot enabled. Updates require review and passing
CI; they are not merged automatically. Dependabot starts using this configuration
after it reaches the default branch.

To update manually, change the exact aiobotocore pin, then run::

    uv lock --upgrade-package aiobotocore
    uv sync --frozen --no-default-groups --group dev --all-extras
    uv run --frozen --no-default-groups --group dev --all-extras pytest

Review failures in ``tests/test_patches.py`` against the dependency source before
accepting new source digests. A digest change can be a docstring change or a real
behavior change. Never refresh these digests without reviewing the source.
The lockfile records the tested boto3, botocore and s3transfer versions. Each
application should keep its own lockfile too.

CI covers client/resource creation, S3 transfers and cancellation, DynamoDB,
client-side encryption and the optional Chalice integration. It installs all
extras. The package is also built and its metadata checked. Repeat the matrix
when changing the Python support policy.

Releases and downstream use
---------------------------

Use a reviewed tag or full commit SHA from this fork in downstream projects::

    aioboto3 @ git+https://github.com/Marware/aioboto3.git@<full-commit-sha>

Version numbers are generated by setuptools-scm. For a release, update the
changelog, tag the tested commit and download the wheel from that tag's CI run,
or distribute it through your package index. The upstream PyPI publish job runs
only in ``terricain/aioboto3``; tags on this fork build and test without trying
to publish to the upstream package.
